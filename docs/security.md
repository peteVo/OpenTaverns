# Security model

Saved room snapshots contain private state and credentials and stay outside web assets in a gitignored data directory. The server operator's `/manage` register uses a separate random key and HttpOnly, SameSite=Strict admin cookie; ordinary seat credentials cannot list or delete tables. Management summaries omit private state. Origin checks cover deletion, and a deleted room cannot be recreated by bot loops or socket-close callbacks. See [table storage](table-storage.md) for disk protection, key rotation and restart recovery.

The server owns rooms, identity mapping, seeds, random state, decks, phases, assets, inventories, trades, obligations, and victory. Browser state is display data. Each game has its own authoritative `applyAction` function that clones state and checks its rules and invariants before the room changes. Invalid actions cannot partly mutate a room. Hearthlands keeps a private action history; Saigon Grid keeps a public financial ledger and event history.

The browser cookie is a random opaque 256-bit credential. It is `HttpOnly`, `SameSite=Lax`, scoped to `/`, and `Secure` on HTTPS. A nickname or room code alone cannot reclaim a seat. HTTP writes and WebSocket upgrades check same-origin requests. No API accepts user-supplied player IDs for authentication. A spectator can send a WebSocket message but the server rejects gameplay actions.

For Hearthlands, the public projection includes only Material and card counts, remaining deck count, and public Renown until the match ends. Exact inventories, unrevealed Chronicle Cards, deck order, private RNG key/counter, and validated action history stay on the server. Public events avoid hidden Material names when stolen or drawn. The world seed is withheld until game over; production and hidden-card randomness use an independent 128-bit key generated by the server. HMAC-SHA-256 derives each draw from that key and a counter, with rejection sampling to avoid modulo bias.

Saigon Grid Holdings, Credits, trades, and the ledger are public table information. Its projected view excludes the random state and undrawn City and Civic Event deck order. The server rolls both dice and validates bids, trades, ownership, and debt actions.

The current single-process design serializes action handling through Node's event loop. Each accepted client action ID is recorded per seat, so repeating the same message is acknowledged without applying it twice. Offers have IDs and are removed when settled; auction bids and Saigon Grid trades also carry revisions. The newest WebSocket connection controls a seat when the same session opens multiple tabs. A future multi-instance deployment requires a shared store and transactional per-room action ordering before it is safe to scale horizontally.

Tests cover turn and phase tampering, illegal placement, ownership, private projection, trade replay, simultaneous acceptance attempts, guessed sessions, cross-site writes, and spectator submission. A broader external security audit remains appropriate before operating a large public service.

Tidecall live public state has no hands, unrevealed Forecast values, Compass choices, future Tide order, undealt cards, random state or action log. Each seat receives only its own private section. Spectators get no private section. All private locks stay server-side until simultaneous reveal; public history announces only played cards and revealed choices. Deck-conservation and score invariants run after every action and in simulations. A transport match ID rejects delayed actions from a previous match; round/trick IDs, revisions, immutable locks, once-per-match Compass and per-seat UUIDs prevent duplicate or late intentions. Rematch is host-controlled and requires all human seats connected or explicitly replaced by bots.

## Werewolf privacy

Night roles, spares, votes, action history, victim, causes and RNG stay server-side. Public night revisions and equal padded deadlines do not reveal who submitted a response or whether a scheduled character is present. Own character/knowledge and living pack information are explicit entitlements; dead wolves no longer receive pack updates. Public death reveals do not include private knowledge. Strict schemas, cookie-chosen actor, latest-tab control, match/window guards and retained retry IDs cover hidden decisions. Post-game truth is intentionally complete. Saved data directories contain these secrets and must remain private. See the [engine privacy model](werewolf-engine.md).

## Mosaic transactions

The selected offer must exist, the actor must own the active turn, and both tile IDs must match that offer. Revision, round, turn, cells, emptiness and sequential adjacency are checked before any mutation. Strict schemas reject partial/oversized placement arrays, invented identities, score changes, forced victory and future draws. Projections exclude bag order/RNG/seed. Spectators remain read-only. Current-tab policy, match identity and persisted action UUIDs cover duplicates, reconnects and stale submissions. Browser tests include HTTP-compatible UUID fallback for phone clients.
